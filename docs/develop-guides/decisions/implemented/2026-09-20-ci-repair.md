# 持续集成与可选文档发布

状态：implemented
类型：bug-fix
Owner：.github/workflows/deploy.yml

## 问题

文档构建依赖未启用的 Pages，系统测试使用不可拉取的镜像地址及错误宿主端口，Python 格式检查不通过，部分测试替身落后于当前接口契约并触发真实外部连接。

## 决策

文档自动构建与可选发布分离。deploy.yml 保留依赖安装、构建和产物上传；仅 vars.ENABLE_DOCS_PAGES 为 true 的 main 推送执行 Pages 配置及发布，维护者须先在仓库启用 Pages。未开启发布时不影响构建质量检查。

Compose 使用官方 Quay 分发的同版本 MinIO；system-tests.yml 的宿主探针与 Compose 的 5051 端口一致，容器端口仍为 5050。初始化账号同时提供给 integration fixture，避免缺少凭据跳过真实接口验证。

Python 格式与 import 顺序遵循原 Ruff 配置，不增加忽略规则。测试替身补齐 repository 的事务参数、runtime workspace manifest 和工具元数据，并隔离不属于单元测试的 checkpoint 外部读取。integration 的 schema 预检在同一临时事件循环内通过 finally 关闭 PostgreSQL 池，避免 schema 已通过却无法退出。原业务断言保留，新增事务透传及工具元数据真假分支验证。

## 替代方案

禁用工作流、忽略失败或缩减测试范围无法证明质量。默认自动开启 Pages 会发布尚未配置的继承文档站，因此发布保持显式启用。

## 后果

工作流正常反馈实际构建与测试结果；可选网站发布需维护者单独启用。MinIO 只变更镜像分发地址，版本和存储格式保持一致。工程助手提示词的完整字符串与修改前一致。

- Ruff check、format --check、import sorting 检查通过，248 个 package Python 文件满足格式规则。
- 新旧 MinIO 镜像 ID 相同，官方 Quay 拉取及隔离运行版本检查通过；现有用户服务未重启或清理。
