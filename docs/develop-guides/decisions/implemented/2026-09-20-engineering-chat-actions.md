# 工程自然语言任务与双库辅助审查

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/changwei_chat.py

## 问题

工程 Skills 需要通过聊天调用实际业务动作；长资料预览不能覆盖后续章节；天气网络异常需要有限等待与明确反馈。生成的 Word 还需出现在当前对话中，同时保留工程成果和个人归档。

## 决策

内置工程助手预加载工程技能，通过三个窄工具查询授权工程、保存草稿、确认并导出。服务复用工程 repository 的 uid、成员权限和 revision 检查。新建任务使用 thread/tool-call 派生 ID 与 PostgreSQL advisory transaction lock 去重；更新检查版本。草稿不自动确认，最终导出工具始终经过 HITL，包括 always_trust，且拒绝子 Agent 执行。确认、版本和成果字节在同一事务中提交；文件副本失败保留数据库成果并提示。

资料列表提供预览，material 动作按已授权且已确认的资料 ID 分页读取，每次最多 12000 字符并返回 next_start。方案审查 Skill 在知识能力开启时复用五个只读检索工具；规范标准与项目资料分别检索，关键结论回看上下文，待审正文不充当依据。规范名称清单不代表全文或有效性证明；历史批复隔离，OCR数字和单位由人工复核。

导出工具通过当前可信 Workdir 发布对话副本，并将路径写入既有 Command artifacts 状态，沿用前端文件卡片和线程下载鉴权。ToolMessage 同时返回实际发布成功的 artifact_paths，聊天正文从本轮工具结果提取文件卡片；失败或旧消息缺字段时不猜测路径。个人空间 outputs 归档保持原路径。路径发布遵守 Workspace no-follow 读写边界，不增加 Agent 的通用文件或沙盒权限。

天气对安全 GET 的传输失败最多重试一次，设总时限；前端显示固定、可操作的提示。QWEATHER_HTTP_PROXY 可单独指定天气代理，空值沿用 HTTPX 环境代理设置，不代表强制直连。

## 替代方案

仅添加提示词无法保存业务任务；另建聊天队列会重复已有 AgentRun 和 worker。模型额外调用 present_artifacts 容易漏调用且依赖通用工作空间能力，因此由已批准的导出工具发布文件状态。直接登记用户根 outputs 路径会被旧聊天路径兼容逻辑改写，当前 Workdir 副本避免改变普通聊天的兼容语义。

## 后果

用户可以自然语言办理监理日志与方案文档辅助审查，缺失事实时追问，修改后重新核对。系统不承担结构计算、专业签审或规范有效性自动认定。模型仍可能误判、扩大审查范围或输出不可解析的长工具参数；限制范围、精简意见、页段回查与人工核对共同约束结果，不能用少量演示推导准确率。
