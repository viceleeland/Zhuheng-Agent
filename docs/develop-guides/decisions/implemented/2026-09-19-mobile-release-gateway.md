# 手机客户端的静态发布入口

状态：implemented
类型：feature
Owner：docker/gateway/nginx.conf

## 问题

安卓客户端需要稳定的 HTTPS 入口及实时语音 WebSocket。Vite 开发服务包含源码和调试入口；仅把开发端口连接到公网隧道不能满足交付边界。

## 决策

发布入口由 Nginx 提供前端生产构建，并代理已有 API。网关保留 WebSocket Upgrade 和长连接，关闭流式响应缓冲，上传上限覆盖工程资料入口。Nginx 配置负责阻断开发源码、环境文件、接口文档、管理初始化、CLI 登录及匿名对象存储路径；业务 API 的登录、工程成员权限和成果下载授权仍由后端拥有。

登录限流使用网关观察到的连接来源，转发来源头由网关重写。访问日志只记录路径和状态，不记录查询字符串、认证头或请求体。HTML 禁止缓存，带哈希的静态资源长期缓存。启动脚本验证生产页面、公开 API 健康 JSON 与本机后端 readiness 后才报告网关启动成功；readiness 不通过公网暴露。

网关显式将 `.mjs` 映射为 JavaScript MIME，保证 PDF.js 的模块 worker 可在保留 `nosniff` 的情况下加载。默认二进制 MIME 会被浏览器拒绝，表现为 Word 转 PDF 已成功而网页预览失败。

Windows 本机入口绑定回环地址。Linux Compose 使用固定摘要的官方 Nginx 镜像、非 root 用户、只读根文件系统和独立项目名。互联网发布由隧道配置拥有，用户确认发布后才能启用；隧道开启状态与外部 DNS、外部访问成功分别验证。

## 替代方案

直接公开开发端口会扩大文件与调试入口的暴露范围。要求每部手机安装私网客户端增加试用步骤。公网 HTTPS 网关适合本机演示；客户正式部署使用客户服务器与域名，避免把演示电脑的在线状态当作生产可用性保证。

## 后果

网关后的登录限流可能共享隧道来源地址。通用聊天旧式匿名图片链接可能无法加载，工程成果通过已验证的鉴权下载接口访问。本机休眠、隧道服务或域名解析异常仍会影响手机连接。公网 DNS 尚未验证成功时，发布报告必须明确说明。

## 验证

公网 PDF.js worker 的 `.mjs` 请求由 `application/octet-stream` 修正为 `application/javascript`，配置检查及启动就绪探针通过。浏览器绕过旧缓存后，实际生成的监理日志在成果归档中成功呈现两页预览，随后恢复正常缓存设置。已有缓存的客户端需强制刷新；该验证不包含原版模板排版与天气服务可用性。

Windows 网关与隔离 Linux 容器均执行 16 项 HTTP 与 WebSocket 探针，开发路径、初始化与匿名受限路径符合预期。认证后的登录、工程读取和已有 Word 下载经本机 HTTPS 入口成功，下载字节与直连 API 的 SHA-256 相同。实时语音经该 HTTPS 入口完成真实云服务转录，使用合成音频，未替代手机实麦验收。

外部 DNS 返回公网入口地址，强制通过该公网 IP、保留原域名 SNI 与证书校验的 HTTPS 登录、工程读取、Word 下载成功，成果字节与直连 API 相同。真实手机运营商网络、客户服务器反向代理与长期公网可用性属于独立部署验收范围。

`scripts/test-public-gateway-readiness.ps1` 在独立进程提取检查函数并使用响应桩，覆盖依赖未就绪但 liveness 返回 200、健康地址返回 HTML、开发入口、降级和缺失字段的拒绝，以及正常响应的接受。该测试不启动服务，不替代真实网关请求验收。
