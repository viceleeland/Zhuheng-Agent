# 客户离线镜像交付与核心业务编译

状态：proposed
类型：architecture
Owner：deploy/customer/api.Dockerfile

## 问题

开发环境依赖源码挂载、本机路径与现存数据，不能直接作为客户安装包。客户需要 Linux x86_64 的独立安装与运维流程，并要求提高核心业务代码的逆向成本。

当前交付范围由用户收窄为镜像原理、真实前端镜像样本和客户部署操作说明。完整后端镜像构建、源码保护验收及真实客户安装和恢复演练不执行；以下完整交付方案保留为 proposed，不能作为生产验收通过的依据。

## 提案

交付固定版本的应用镜像、基础服务镜像、部署配置及安装、备份、恢复脚本。客户实例使用独立 Compose project 和空数据目录，密钥在部署时生成或填写，不复制开发环境的凭据与业务记录。API 和 worker 运行相同发布镜像，迁移器独占 Schema 变更。

核心工程业务 Python 模块编译为原生扩展，发布构建明确记录保护范围，产物不保留对应 Python、字节码或生成的 C 源文件。前端只交付生产构建，不携带 source map。镜像构建和归档检查覆盖层中的文件，不以容器当前目录中的删除结果替代检查。

源码保护的目标是提高直接复制和逆向的成本。容器镜像本身不提供保密性，客户管理员可读取文件、内存和可执行文件；动态语言依赖、框架、协议、提示词字符串和浏览器 JavaScript 的可见范围在交付说明中披露。不实现未经需求确认的联网授权或远程停用机制。

## 替代方案

直接复制开发目录会带入路径与运行配置，不能形成独立可验收的安装。仅删除最新镜像层的源码会保留底层副本。只编译字节码容易被还原。将所有 Python 模块盲目编译会增加动态导入与反射风险，因此保护范围由实际业务模块和编译后的验证共同决定。

## 验收标准

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 空目录可安装 | 源码挂载或隐含依赖 | deploy/customer/runtime/install.sh | 独立实例真实启动、登录及工程产物 | 缺少镜像或校验不符必须退出 | Not run |
| 核心业务由原生扩展运行 | .py 或 .pyc 静默回退 | deploy/customer/compile_core.py | 模块实际加载路径、归档层扫描、业务回归 | 故意加入保护模块源码时构建检查失败 | Not run |
| 客户数据独立持久 | 实例串用或容器重建丢失 | deploy/customer/runtime/restore.sh | 创建数据、重建后回读、恢复到新实例 | 禁止覆盖非空恢复目标 | Not run |
| 无开发凭据和资料 | 构建上下文或层泄露 | deploy/customer/prepare_build.py | 允许列表构建、镜像配置与层检查 | 配置缺项、默认秘密必须拒绝 | Not run |
| 交付范围明确 | 未配置云服务冒充可用 | deploy/customer/runtime/install.sh | 功能验收与未验证项记录 | 未配置模型时明确提示 | Inspected |

## 风险

编译后的异步函数、装饰器和类型注解需要真实 API、数据库及文档生成验证。首次安装依赖 Docker Engine 与 Compose；离线镜像可离线导入，但云模型、天气和实时语音仍需要网络与客户密钥。当前业务试用版的规范审查、复杂台账及现场语音验收边界继续有效。开源组件的许可证与通知随产物保留。
